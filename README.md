# CareerPilot AI — private single-user MVP

**Features:** upload PDF/DOCX/TXT resume; save verified experience evidence; tailor resume to pasted job descriptions; generate interview questions and STAR answers; export editable Word documents; manually track job applications.

**Scope:** This is a starter MVP, not a production-hardened multi-user product. AI drafts require review. It does not browse LinkedIn, scrape websites, or submit applications. Uploaded documents are parsed in memory; extracted text is saved in PostgreSQL. Generated drafts persist only in the current browser session until downloaded. Do not use employer-confidential or sensitive client data without authorization.

## 1. Prerequisites

- GitHub account
- Render account
- OpenAI API account with project API key and separate API billing enabled
- A unique workspace password (16 characters minimum)
- Optional: Docker Desktop and Git for local testing

## 2. Create a PRIVATE GitHub repository

1. At https://github.com/new enter `careerpilot-ai`.
2. Select **Private**, and create an empty repository (do not add README or .gitignore; this starter contains them).
3. Download/unzip this starter folder; open Terminal inside it.
4. Run:

```bash
git init
git add .
git commit -m "Initial private CareerPilot MVP"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/careerpilot-ai.git
git push -u origin main
```

GitHub may ask you to sign in. Do **not** add `.env` or resume files. The included `.gitignore` excludes them.

## 3. Create a persistent Postgres database on Render

1. Sign in to https://dashboard.render.com.
2. Choose **New > Postgres**.
3. Use name `careerpilot-db`, choose a region, and choose a **paid** plan if you need real persistence. **Render's free Postgres expires after 30 days and has no backups.**
4. Once ready, copy the **Internal Database URL** from Render's database dashboard. It should only go into the web service's Environment settings, never GitHub.

## 4. Create the Docker web service on Render

1. In Render, authorize GitHub with access to the **specific private repository**, not all repositories if possible.
2. Click **New > Web Service** and select `careerpilot-ai`.
3. Choose runtime **Docker** (Render detects the root `Dockerfile`), branch `main`, and the appropriate service plan.
4. Under the service's **Environment** section add:

| Key | Value |
| --- | --- |
| `APP_PASSWORD` | Long, unique password (16+ characters) |
| `OPENAI_API_KEY` | Secret API key from the OpenAI API platform |
| `OPENAI_MODEL` | `gpt-4.1-mini` (change to supported model if unavailable) |
| `DATABASE_URL` | **Internal Database URL** from Render Postgres |

5. Deploy. Render builds the Docker image, installs dependencies, and launches Streamlit on its assigned `PORT`.
6. Open the `https://...onrender.com` address generated by Render. Enter your workspace password.
7. In **Career evidence**, upload your master resume, then save truthful career evidence with any validated outcomes.
8. In **Resume studio**, paste a job description and generate a draft. Review **all claims** and download a Word draft.
9. In **Interview coach**, generate Q&A; download to Word and refine your stories.
10. In **Job tracker**, manually save postings and your application status.

**Note:** The web app URL is publicly reachable unless you add network restrictions or managed authentication; the starter uses a single shared password gate. This is suitable for limited personal experimentation, not regulated data or multi-user operations. Consider managed OIDC login, rate limiting, security audit, encryption and monitoring before serious use.

## 5. Optional local Docker test

1. Install Docker Desktop.
2. Copy `.env.example` to `.env` and fill `APP_PASSWORD`, `OPENAI_API_KEY`, and `OPENAI_MODEL`. Leave the placeholder `DATABASE_URL` alone: Docker Compose overrides it with the local Postgres service URL.
3. Run `docker compose up --build`.
4. Visit http://localhost:8501.
5. Stop with `docker compose down` (preserves DB volume). `docker compose down -v` deletes local database data.

## 6. Updating and deploying

Edit code, then run:

```bash
git add .
git commit -m "Describe my feature"
git push
```

With auto-deploy enabled, Render rebuilds from `main`. Your PostgreSQL records persist across web-service deployments.

## 7. Portability

- Any Docker-capable provider can run the container, provided you set `APP_PASSWORD`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `DATABASE_URL`, and `PORT`.
- The PostgreSQL database may be externally managed (Neon/Supabase/Cloud SQL/etc.), but access rules and TLS vary by provider.
- For a true production app, move from the shared-password authentication to an identity provider, add database migrations, retention/export controls, audit logs, observability, and automated functional tests.

## 8. Privacy checklist before GitHub visibility changes

- No private documents, credentials, real sample data, or `.env` files in current files **or commit history**.
- Review GitHub Actions logs, README, commit messages, and screenshots.
- Check for confidential client details and copyrighted course code.
- Change GitHub **Settings > Danger Zone > Change repository visibility** only after cleanup.
- It may be safer to publish a separate sanitized portfolio repository and keep the personal deployment private indefinitely.

## 9. Current feature gaps

- No automated discovery, LinkedIn scraping, application submission, resume templates, sourcing audit log, or evaluation framework yet.
- Password gate is not enterprise-grade auth. No login rate limit, password reset workflow, or session invalidation across devices.
- PDF extraction handles selectable text; image-only PDFs will need a separately approved extraction workflow.
- Word export is basic and may need a refined template.
- This starter has a syntax-only CI check, not full integration tests.
